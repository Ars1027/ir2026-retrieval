# 附加题一：段落 BM25 重排

在基础 BM25 的候选内，对每篇原文的滑窗段落计算局部 BM25。等权融合衡量前级名次与局部匹配，消融对照衡量只用局部匹配时的结果。三个配置走同一个 `agent.bm25_solution` 入口。

## 方法与实验控制

三组用同一个索引、词项处理和查询，召回前 200 个 BM25 词块，按最佳词块名次聚合文档。前 100 个不重复文档构成可重排候选。基础组用前级排序直接返回 10 篇。重排使用 160 词窗口、120 词步长，在本题候选的窗口上构建 SQLite FTS5 内存索引。取每篇最高段落 BM25 分，得到段落名次。段落词项经 `porter unicode61` 归一化，BM25 使用 SQLite 默认参数。

| 配置 | 最终文档排序 |
| --- | --- |
| `configs/bm25.json` | 基础词块 BM25 聚合名次 |
| `configs/bonus1/fusion.json` | 前级名次与段落名次的等权 RRF |
| `configs/bonus1/passage.json` | 去掉前级 RRF 项，只按段落名次排序 |

RRF 常量为 60。段落得分或融合得分同分时按前级名次消歧。段落评分的真实跨度及各级名次写入 `passage_rerank` 事件，最终证据与答案仍由项目的公共流程根据原始命中词块组装。三组在 600 秒内返回最多 10 篇文档及 5 段原文，均使用原有抽取式答案和本地计算。

## 验证集结果

| 完整 dev50 | 基础 BM25 | 段落融合 | 仅段落 |
| --- | ---: | ---: | ---: |
| Hit@1 | 0.20 | 0.16 | 0.22 |
| Hit@5 | 0.30 | 0.32 | 0.34 |
| Hit@10 | 0.40 | 0.42 | 0.42 |
| EvidenceRecall@10 | 0.199889 | 0.212548 | 0.226460 |
| AnswerEM | 0.00 | 0.00 | 0.00 |
| 正常完成 / 50 | 50 | 50 | 50 |
| 平均每题秒数 | 0.4648 | 1.0145 | 1.0010 |
| P95 每题秒数 | 0.5217 | 1.6646 | 1.4051 |

融合相对基础组新增 2 道 Hit@10 命中，丢失 1 道。精确 McNemar 检验双侧 p 值为 1.0，样本中的净增只有 1 题。去掉前级融合项后，新增 3 题并丢失 3 题，Hit@10 持平，Hit@1 与证据文档召回提高。原有混合检索的历史 Hit@10 为 0.44，见[基础结果](RESULTS.md)。本轮受控比较以同次复跑的离线 BM25 为基线。

通过逐题轨迹核对，三组使用的候选文档及前级顺序一致，两种重排的段落分数与名次也一致。18 道题在第一阶段就没有召回任何答案文档。另有 12、11、11 道题的答案文档在候选内，最终排在前十之外。

融合和仅段落组的重排阶段平均耗时分别为 0.532 和 0.526 秒，主要开销来自读取候选、切段和构建内存索引。三个配置共用大小为 207,921,892 字节的 BM25 索引，构建耗时 40.31 秒。内存段落索引逐题释放。三组模型工具调用和模型 token 均为 0。耗时来自一次串行测量。

## 轨迹分析

下列名次依次为基础组、融合组和仅段落组。案例以相同的验证标注文档为参照。

- **局部线索集中（12 → 5 → 1）**。在长档案目录中，单个窗口同时包含人物关系、交易和地址等线索。局部匹配使该文档进入前十。仅段落组提升更大。
- **前级名次提供补偿（8 → 10 → 14）**。目标文档中回答事件年份的句子和题干关键词密集的图片说明位于不同位置。最高分窗口落在图片说明，前级名次使融合组仍能命中该文档。
- **融合后失去命中（6 → 20 → 61）**。目标访谈的最高分窗口只覆盖了题目的一部分工作经历。其他文档的局部词项重合更集中，等权融合将目标文档挤出前十。
- **初次召回遗漏（候选池外）**。一篇论文的正文集中描述研究主题，题干却主要给出作者履历。局部重排只能处理已经进入候选池的文档，无法补回这次遗漏。

四例展示了文档命中和原文支持之间的差异。所有抽取式结果的 AnswerEM 都为 0。通过原文逐字检查的引用仍需人工核验能否支持最终答案。

## 复现

本实验使用 Apple M5、macOS arm64、Python 3.13.15、NumPy 2.5.4、SQLite 3.53.2。需要支持 FTS5 的 SQLite 和课程原始数据目录。依赖、数据验收、切块和 BM25 索引构建见 [README](../README.md#基础检索)。

先用 `--split train --limit 3 --check` 对三个配置冒烟。正式运行按下列顺序串行执行，同一个输出路径只能运行一次。

```bash
python scripts/run_baseline.py --method bm25 --split dev \
  --output output/bonus1/dev_baseline --check --evaluate
python scripts/run_baseline.py --method bm25 --config configs/bonus1/fusion.json \
  --split dev --output output/bonus1/dev_fusion --check --evaluate
python scripts/run_baseline.py --method bm25 --config configs/bonus1/passage.json \
  --split dev --output output/bonus1/dev_passage --check --evaluate
python scripts/run_baseline.py --method bm25 --config configs/bonus1/fusion.json \
  --split test --output output/bonus1/test_fusion --check
```

验证标签由评测程序在检索完成后读取。测试轮次使用预先冻结的融合配置，50 题均为 `ok`，通过官方提交检查。测试标签由教师持有。完整运行结果、问题、原文与逐题轨迹在课程内部交接，公共记录见 [records/bonus1](../records/bonus1/)。[课程数据使用约定](../DATA_USE.md)
